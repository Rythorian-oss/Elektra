01 · Welcome

A small sphere with a complete assistant behind it.

THE ELEKTRA GUIDE

Elektra is a Windows desktop voice assistant designed around a movable, luminous plasma orb. Speak a question, see an answer, and hear it spoken back. The app combines offline speech recognition, local command handling, knowledge providers, optional feedback-based learning, and a set of practical desktop controls.

On-deviceVosk speech recognition runs with a local model.
Opt-inLearning and voice-sample storage start disabled.
Human-ledCorrections and lesson repetitions are user verified.
01

Listen and understand

A configurable wake phrase or a manual listening action starts active listening. Vosk recognizes the utterance locally; the app routes it through explicit commands and supported question handlers.

02

Answer and speak

Arithmetic and the local clock can be handled on-device. Supported questions may use weather/time, Wikipedia, and DuckDuckGo Instant Answer providers. Elektra presents the response and reads it aloud.

03

Help with desktop tasks

Use the orb and tray to listen, stop speech, hide or restore the assistant, choose a microphone, or exit. A fixed set of Windows folders and applications can be opened by voice.

04

Improve with supervision

If enabled, explicit feedback, exact transcript corrections, and verified voice samples are stored locally. Scheduled ML.NET intent training is separate from the Vosk speech model.

How to read this guide. It distinguishes shipped behavior from features that are not yet present. The diagrams explain system flow; charts show implementation limits and design structure—not benchmark results or claims that learning has improved accuracy in real-world use.

Design principle

Let the recognizer interpret speech, let predictable handlers perform supported actions, and let the user decide whether corrections and microphone samples may be retained.

02 · The interface

The orb is the assistant's face.

FORM · COLOR · MOTION

Elektra appears as a compact, floating glass-and-plasma sphere. Its design combines a dark blue core, a bright cyan highlight, a thin luminous rim, and a subtle halo. The sphere is intentionally lightweight on screen: move it by dragging, double-click to listen, and right-click for the glass-styled action menu.

The orb is not just decoration. Microphone energy subtly influences its animated surface. The lighting palette also changes with the assistant's activity, giving a glanceable cue while the response HUD presents the actual words.

Listening · aqua and cyan
Thinking · rose and warm amber
Speaking · emerald and mint
Warning · red tones

One orb, several controls

  • Double-click: begin listening.
  • Right-click: open the orb menu.
  • Drag: reposition the orb; its location is saved.
  • Win + Alt + E: show or hide Elektra.
  • Ctrl + C: copy the displayed answer.
  • Esc: dismiss the response panel.
  • System tray: restore, hide, select a microphone, manage startup, or exit.
03 · Interaction

Speak naturally. Stay in control.

A PRACTICAL GUIDE

Ask a spoken question

  1. Say the configured wake phrase, or double-click the orb.
  2. Speak a concise question while Elektra is listening.
  3. Read the answer in the response panel and hear it spoken.
  4. Copy with Ctrl+C, dismiss with Esc, or use the on-screen controls.

Use the right-click menu

Right-click the sphere for Listen Now, Stop Speaking, Local Learning, Voice Practice, microphone selection, Hide to Tray, and Exit. Learning and automatic voice-practice options appear here; audio practice requires the separate recording consent.

Useful spoken commands

“Stop speaking”“Hide Elektra”“Show Elektra”“Forget context”“Open Documents”“Open Notepad”“Find Eiffel Tower”

Commands are handled through known, fixed handlers. The application does not execute arbitrary spoken shell commands.

Location confirmation

When a location search is requested, Elektra repeats the place and asks for confirmation before searching. A correction can be spoken. If lookup is enabled, the place is sent to the configured geocoding service and the found coordinates can open in Google Earth web.

Online lookup is distinct from recognition. Vosk recognition runs locally. A question may then be sent as text to a configured online knowledge provider. Disable online lookups in the assistant configuration to keep supported local functions such as arithmetic and local time available without those network lookups.

A spoken exchange, step by step

“Elektra, what is 12 plus 5?”
The speech model recognizes the request. The supported arithmetic handler calculates locally. The answer appears on screen and is read aloud.
04 · Under the surface

From microphone to useful answer.

SYSTEM ARCHITECTURE

Elektra uses a staged pipeline. Audio recognition, command handling, knowledge retrieval, and optional learning are separate responsibilities. This makes the boundaries easier to inspect: a predicted intent can help route a question, but it does not grant permission to perform an arbitrary computer action.

Speech layer

Microphone frames are processed locally. RNNoise is used when available; an adaptive energy detector remains as a fallback. Audio is resampled for Vosk.

Routing layer

Follow-ups, local commands, and supported actions are handled before the optional ML.NET intent classifier and general knowledge resolution.

Knowledge layer

The orchestrator can use local context and cache and consult ordered providers. First usable results win; provider feedback may change provider ordering when learning is enabled.

Offline does not mean every task is offline. Speech recognition is local. Arithmetic and local time are local. Weather, Wikipedia, DuckDuckGo Instant Answer, and geocoding need network access when those providers are used.

06 · Improvement with consent

Learning is explicit, local, and bounded.

FEEDBACK → REVIEW → EVALUATE

Elektra's learning feature is not a self-modifying conversation model. It is an opt-in workflow for keeping labeled examples, corrections, user memories, provider feedback, and—under a second consent—verified microphone samples. Scheduled evaluation decides whether a candidate intent model may be promoted.

Feedback on a question

With Local Learning enabled, Elektra can repeat a recognized question and ask whether it heard correctly. A confirmation records a labeled intent example. A correction can be typed and saved as an exact transcript correction.

Answer feedback

“That worked,” “That didn't help,” and “I meant…” record deliberate feedback. Provider ratings can influence provider order; this is score-based ordering, not a separately trained ranker.

Explicit memory

Memories are entered deliberately, saved locally, searchable, and individually deletable. They are separate from the intent classifier and are not silently inferred as facts.

Model safety gate

The scheduled ML.NET candidate must pass sample-count, class-count, cooldown, validation, and baseline requirements. The prior intent model can be restored using model rollback.

Two kinds of consent—not one

Intent training is not voice adaptation

The ML.NET model classifies supported utterances into a small intent set, such as a knowledge question or location search. It uses text examples and is evaluated before promotion. It does not change how Vosk acoustically recognizes the microphone.

Repeat-after-me lessons add verified audio/transcript examples to an on-device corpus. As currently implemented, Elektra does not invoke Kaldi/Vosk acoustic training, compare candidate-model word error rates, or promote and roll back Vosk acoustic models. The corpus is preparation—not an already-trained recognizer.

Voice lesson flow. Right-click the orb → Start Voice Practice Lesson. Elektra reads a known correction, verified phrase, or short example. Repeat it; a matching Vosk transcript allows the sample to be saved locally. Incorrect attempts are discarded. Say “skip” to end. Automatic lessons are off by default.
07 · Trust & boundaries

Privacy is a set of choices and limits.

WHAT STAYS · WHAT MAY LEAVE

Local by design

  • Vosk processes microphone audio with a local model.
  • Ordinary listening does not persist raw audio.
  • Voice-sample collection is separately opt-in and stores verified WAV recordings on this device.
  • Learning records and preference files are stored under the local application data directory.
  • Review and deletion controls are available for learned records.

Network when needed

  • Online knowledge questions may send query text to configured providers.
  • Weather and web-based information depend on provider availability.
  • Place searches send the place query to the configured geocoder.
  • Speech recognition being local does not make a later provider request local.
  • Do not speak secrets or sensitive details into online lookups.

What learning can—and cannot—control

Learning can help

  • Improve intent routing from labeled examples.
  • Apply exact, user-entered speech or location corrections.
  • Adjust provider ordering from explicit helpful/not-helpful feedback.
  • Recall memories the user explicitly saved.

Learning cannot authorize

  • Run arbitrary shell commands or executables.
  • Skip location confirmation before a search action.
  • Automatically execute Windows or security actions based on a correction.
  • Claim answer correctness just because a transcript was confirmed.
Recorded audio is plaintext. Opted-in WAV samples and learning text are stored locally without the separate protected-folder encryption feature. Use voice-sample collection only if you accept that storage risk. The feature does not send audio to knowledge providers.

The security and privacy descriptions in this booklet reflect documented application behavior and configuration. They are not a formal security certification or guarantee that all operating-system and provider behavior is risk-free.

08 · Resource awareness

Built with practical bounds.

CAPACITY · NOT BENCHMARKS

Several learning and cache stores have explicit limits to prevent unbounded growth. These are configuration and implementation caps, not measurements of runtime speed, memory usage, or user experience.

Cache

Knowledge answers can use an in-memory cache and, where available, a SQLite-backed persistent cache. The configured memory-cache size limit is 512 entries; the persistent knowledge store is capped at 10,000 entries with expiry behavior.

Learning stores

Intent examples are capped at 10,000; explicit memories at 500; speech corrections at 1,000; voice audio samples at 500. These are retention ceilings, not performance results.

Audio buffers

When voice-sample consent is active, active capture is bounded to 15 seconds and the recent in-memory queue is bounded. Disabling consent clears buffered samples.

Measurement status. This booklet reports design and storage bounds. It does not report a heap snapshot, memory-leak experiment, CPU benchmark, response-latency distribution, or measured reduction in misroutes. Those require controlled runtime profiling and representative use data.
09 · Getting started

Bring Elektra to life.

QUICK START
  1. Prepare Windows. Elektra is a WPF desktop application targeting net10.0-windows. Use the appropriate .NET 10 SDK/runtime and Windows Desktop support for the build you have.
  2. Provide a Vosk model. Place a supported model on disk and configure Assistant:VoskModelPath if the default model path is not suitable. The model directory must contain the expected Vosk folders.
  3. Start listening. Say “Elektra,” double-click the orb, or right-click and choose Listen Now. Speak while the assistant is actively listening.
  4. Choose online features deliberately. Online question providers and location services require network access. Set Assistant:EnableOnlineLookups to false to disable those online lookups.
  5. Enable learning only if wanted. Use the orb menu or the answer-panel setting. Learning is off by default and can be turned off at any time.
  6. Enable audio only with separate consent. In an eligible answer panel, opt in to local voice samples. Audio is saved locally only after verification. Review or clear learning data from the learning controls.
  7. Try a practice lesson. With both required consents active, right-click the orb and choose Start Voice Practice Lesson. Repeat Elektra's phrase; say “skip” to end.

10 · Honest status

What this guide does not claim.

LIMITATIONS & NEXT STEPS

Elektra has a growing set of features, but a careful description matters as much as a compelling one. The following distinctions prevent a user interface, an experimental corpus, or an automated test from being mistaken for proof of broader capability.

No automatic Vosk acoustic retraining

The current application can collect consented, verified voice samples, but it does not include a supported Kaldi/Vosk acoustic-training pipeline, held-out word-error-rate evaluation, acoustic model promotion, or acoustic rollback.

No measured accuracy benefit yet

ML.NET classifier training and evaluation are implemented, but no controlled, representative study demonstrates that it reduces user-visible misroutes in daily usage. A baseline comparison is needed before expanding routing use.

No general web search engine

DuckDuckGo integration uses Instant Answer data; Wikipedia provides summaries and selected facts. Elektra does not crawl the general web or present a page of search results for every question.

No unrestricted autonomous learning

Feedback is explicit, data is locally reviewable, model evaluation is scheduled and gated, and voice capture needs separate consent. A confirmed transcript is not evidence that an answer is factually correct.

A responsible next research cycle

1Collect consented casesKeep labels and purpose explicit.
2Measure a baselineTrack misroutes and abstentions.
3Validate separatelyUse held-out, phrase-grouped examples.
4Promote cautiouslyKeep rollback and human review.
For genuine voice adaptation: choose a Vosk-compatible offline training recipe for the specific base model; convert and validate audio/transcripts in the expected format; reserve speaker/phrase-independent held-out recordings; compare baseline and candidate using WER/CER; and promote atomically with a tested rollback path. None of those acoustic-training steps should be inferred from corpus collection alone.

What Elektra is aiming for

A desktop assistant that feels immediate and expressive, remains predictable when it acts, and becomes more useful only through transparent, user-directed improvement.
